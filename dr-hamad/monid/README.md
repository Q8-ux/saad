# Monid — مسار البحث والتحليل لموقع الدكتور حمد

**الحالة:** تكامل برمجي جاهز على جانب الخادم، لا يعمل مع Monid فعلياً حتى يضيف مالك المستودع مفتاح `MONID_API_KEY` إلى GitHub Actions Secrets ويُشغّل الإجراء يدوياً. لا توجد أي تعديلات على صفحات الزوار أو المحتوى الطبي.

## الهدف

تجميع مقترحات أدوات البحث عن ظهور الموقع في نتائج البحث، وتحديثات إرشادات الركبة والورك، وتحليلات الحسابات العامة على الشبكات الاجتماعية. النتائج **مواد تحضيرية لفريق التحرير** وليست حقائق طبية معتمدة أو منشورات جاهزة.

## التفعيل

1. أنشئ مفتاح Monid من https://app.monid.ai/access/api-keys.
2. افتح `https://github.com/Q8-ux/saad/settings/secrets/actions` وأضف **Repository secret** باسم `MONID_API_KEY`. لا تضع المفتاح في الملفات أو في موقع GitHub Pages.
3. افتح `https://github.com/Q8-ux/saad/actions/workflows/dr-hamad-monid-research.yml` واختر **Run workflow** ثم `topic` و `mode=discover`.
4. نزّل ملف التقرير الناتج من قسم Artifacts في تشغيل GitHub Actions. التقرير محفوظ لمدة 7 أيام ولا يُنشر تلقائياً.
5. عند اختيار خدمة مناسبة، استخدم `mode=inspect` مع `provider` و `endpoint` كما ظهرا في التقرير لمعرفة السعر والمدخلات الصحيحة.
6. **التشغيل المدفوع معطّل عمداً** حتى يُضاف الزوج `provider/endpoint` ومُدخل ثابت خالٍ من البيانات الشخصية إلى `approved-endpoints.json` بواسطة تغيير برمجي ومراجعة. يجب تحديد `maxPriceUsd` لا يزيد عن 0.05 دولار للطلب الثابت. لا تقبل النسخة الحالية خدمات `PER_RESULT` ذات التكلفة المتغيرة. عندها فقط يمكن تشغيل `mode=run` مع `paid_run=true`.

## مجالات البحث المسموحة

| topic | الاستخدام |
|---|---|
| `seo-kuwait` | اكتشاف أدوات تحليل بحث Google وSEO لمحتوى جراحة العظام في الكويت |
| `knee-education` | البحث عن مصادر منشورة حول خشونة الركبة والتوصيات العلمية |
| `hip-education` | البحث عن مصادر منشورة حول عمليات مفصل الورك والتأهيل |
| `social-public` | أدوات تحليل الحسابات والمنشورات العامة دون بيانات مرضى |

## ضوابط صارمة

- **ممنوع** تمرير بيانات مرضى، سجلات طبية، صور مرضى، أرقام هواتف أو استفسارات شخصية.
- لا توليد تشخيص ولا نصائح علاج فردية ولا ادعاء بنتائج أو نجاح إجراءات.
- مراجعة المصدر الأولي وتاريخ التحديث قبل الاستشهاد في مقال؛ راجع المصدر العلمي الأصلية مثل NICE وAAOS وCochrane.
- لا نشر تلقائي في الموقع أو إنستغرام. مراجعة طبية ولغوية واعتماد الطبيب لازمة.
- لم نضف أي صور أو شعارات جديدة؛ الهوية البصرية والخطوط والكاروسيلات الحالية دون تعديل.
- لا تضع مفتاح API في المتصفح لأن الموقع منشور كصفحات ثابتة وشفرة الواجهة متاحة للزوار.
- ميزانية التشغيل المدفوع متوقفة افتراضياً وقائمة الاعتماد فارغة.

## الاختبارات المحلية

```bash
node --test dr-hamad/monid/research.test.mjs
```

ترجع النتائج التجريبية باستدعاءات محاكاة، ولا تثبت وجود اتصال حقيقي أو سعة محفظة Monid. أداة الاكتشاف في `research.mjs` تستخدم الواجهات الرسمية `/v1/discover` و`/v1/inspect` و`/v1/run` و`/v1/runs/{runId}` حسب توثيق https://docs.monid.ai/api/overview.html.

## نطاق التنفيذ ومراجعة المخاطر

الموقع المباشر: https://q8-ux.github.io/saad/dr-hamad/

هذا المسار **لا** يعدّل `index.html` ولا يستضيف خادماً مفتوحاً ولا يكشف بيانات جلسات Monid. آلية النشر المشتركة للمستودع معقّدة؛ لذا من الأسلم اعتماد مخرجات البحث يدوياً أولاً ثم نقل المحتوى الموافق عليه إلى صفحات الطبيب بعملية منفصلة. تظل الإضافات الخلفية معزولة داخل `dr-hamad/monid/` وملف Workflow مستقل.

**نقطة قرار:** عند الحاجة إلى بيانات تحليل مستمرة مع لوحة إدارة، ينبغي بناء خدمة مصادقة منفصلة وتقييم شروط مزودي البيانات وموافقة الطبيب قبل إتاحة أي نتائج علناً.


## تشغيل تلقائي جديد — 12 نوفمبر 2026

- يعمل **تدقيق HTML وSEO الداخلي** محليًا دون مفتاح، ويُصدر `public-audit.json`. يراجع صفحتي `index.html` و`article.html` من المصدر، والعناوين والوصف وروابط الأقسام وحجز وزارة الصحة والتنبيه التثقيفي. لا يقيس ترتيب Google ولا الزيارات.
- يعمل `run-all.mjs` **كل يوم اثنين الساعة 07:15 صباحاً بتوقيت الكويت** عبر GitHub Actions (04:15 UTC)، ويُصدر `weekly-summary.json` تحت Artifacts الخاصة بالتشغيل، دون تغيير صفحات الزوار.
- إذا غاب `MONID_API_KEY`، يستمر تدقيق الموقع دون ادعاء اتصال Monid، ويظهر بوضوح `MONID_AWAITING_KEY__SEO_AUDIT_READY` في التقرير.
- بعد وضع المفتاح السري في إعدادات GitHub، يُفعَّل **اكتشاف الأدوات الأربع وفحص المخططات والأسعار مجاناً** (أول أداتين مناسبتين بكل فئة)، ولا يجري أي `/v1/run` مدفوع.
- `mode=discover` من زر Run workflow يشغّل الفئات الأربع حتى لو اختار المستخدم فئة واحدة؛ هي متابعة عامة لا تنفيذ خدمات.
- `mode=inspect` يعرض مواصفات الخدمة المختارة، بينما `mode=run` يظل مشروطاً بالموافقة المباشرة وقائمة الأذونات وتحديد السعر الثابت.
- لا يُسمح بالبحث في بيانات مرضى أو سحب تحليلات حساب Instagram الخاصة دون تفويض رسمي؛ `social-public` يكتشف فقط أدوات المصادر العامة.
- الاختبارات: `node --test dr-hamad/monid/research.test.mjs dr-hamad/monid/run-all.test.mjs`.

**هام:** وجود Workflow مُجدول لا يعني أن Monid أصبح متصلاً. يجب إدخال مفتاح API في Secrets على GitHub. كما أن غياب `MONID_API_KEY` لا يعالج بإدراج مفتاح داخل مستودع GitHub العام.
