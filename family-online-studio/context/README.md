# سياق استوديو الكتابة

المسار مطبق في خادم الاستوديو عند تجهيز طلب السينارست. يأخذ هوية العمل من عنوان الطلب والمخطوط الجاري، ويعيد استخدام ذاكرة العمل القائمة. المخطوط مصدر الوقائع؛ ملاحظات الكاتب توجيهات، ومقترحات المساعد ليست أحداثاً معتمدة. أعمال باركود وعائلة أونلاين وخارج الستوري مستقلة.

يحتفظ السياق بالمشهد والفقرة المختارين وترتيبهما وبصمة المصدر. يرفض معرفاً غير موجود. عند تجاوز حجم المشهد يختار الفقرة المطلوبة وما حولها بترتيب القصة ويعلن أن السياق مقتطف؛ ويرفض فقرة تتجاوز الحد وحدها بدلاً من استبدالها بصمت.

يسجل manifest.json التزام الخادم وبصمات ملفات التنفيذ ونتائج التحقق. الملف source/project-context.ts نسخة مراجعة لوحدة عامة من الخادم، وليس بديلاً عن خادم الإنتاج أو وحدة مستوردة في حزمة واجهة GitHub Pages. لا يضم هذا المجلد المخطوطات أو بذور الأعمال أو بيانات الوصول.

التحقق في المصدر الكامل: node scripts/check-project-context.mjs ثم node scripts/check-knowledge-memory.mjs وnode scripts/check-studio.mjs ثم npm run build. نجحت الفحوص الاصطناعية والبناء؛ لا تعني هذه النتيجة اختبار جودة توليد حي أو سلامة كل اقتراح إبداعي. لا يحتاج تغيير السياق الخادمي إلى استبدال حزمة الواجهة أو تغيير بوابة الدخول.

أُضيف تحليل النص المستخرج من المرفقات والنص الملصق وتوزيعه إلى مشاهد وحوار ووصف بالنمط الفرنسي دون إعادة صياغة. تبحث الوحدة في كامل المصدر وتعيد مقتطفات مرتبطة بالمشهد والمتحدث. يبقى إكمال الحوار وتعديله طلبًا منفصلًا في محرك التنفيذ القائم.

تُعاد قراءة النصوص المستوردة المحفوظة من أحدث مخطوط عند تحميلها بحساب مصادق عليه، مع نسخة سابقة وحماية الإصدار والمحافظة على التعليقات. لا يُستبدل تعديل الكاتب بملف أقدم. يتاح أيضًا زر «إعادة تحليل النص المحفوظ». نجحت اختبارات التخزين والمتصفح ببيانات اصطناعية؛ تنفيذ الدفعة الحية على حساب الكاتب توقف عند التحقق الشخصي، ولم يُسجل بأنه اكتمل.


أُضيف حفظ دائم للأصول المرفوعة والنص المستخرج في أرشيف خاص لكل حساب، قبل بدء التحليل. تتاح «ملفاتي المرفوعة» في صفحة الأعمال والمساعد للبحث بالاسم وتنزيل الأصل وإعادة استخدام النص، وتبقى الملفات عند إزالة المرفق من الطلب أو فشل التحليل. يُفحص الحجم وبصمة الأصل قبل اعتماد الحفظ. هذا الحفظ لا يسترجع أصل ملف قديم لم يُخزّن؛ النصوص الحالية ونسخها التاريخية تبقى مستقلة.

نجحت اختبارات التخزين باستخدام عمليات R2 الفعلية في Miniflare مع بيانات اصطناعية وSQLite والاتصال الموقّع، واختبارات عزل الحسابات والواجهة. لم تُقرأ أو تُعدّل ملفات الكاتب الحية أثناء الاختبار.


تبدأ استعادة النصوص القديمة تلقائيًا عند تحميل واجهة الحساب المصادق عليه، وتشمل المخطوطات المحفوظة وإصداراتها والنصوص الأصلية المستخرجة إذا كانت محفوظة فعلًا. تتبع الاستعادة مؤشرًا محفوظًا وتستأنف بعد انقطاع الاتصال، دون تعديل المخطوط أو استبدال أحدث نص بإصدار أقدم. تمنع بصمة المحتوى تكرار النسخة نفسها، وتُستبعد الأعمال المحذوفة وحسابات الآخرين.

تُوسم الملفات المستعادة بمصدرها وتاريخها ورقم إصدارها، ويظهر «تنزيل النسخة المستعادة» منفصلًا عن «تنزيل الأصل». يحفظ تنزيل JSON المحتوى المخزن كاملًا؛ يتيح النص المقروء استخدام الحوارات والمشاهد في المساعد. أسماء الملفات والبصمات وحدها لا تُعتبر أصلًا محفوظًا. إعادة استخدام نسخة مستعادة لا تعيد تصنيفها بوصفها ملفًا أصليًا.

نجحت اختبارات الاستعادة بقاعدة SQLite وعمليات R2 الفعلية في Miniflare، بما فيها الانقطاع والتزامن وإعادة الفحص وعزل البادئات والحسابات وعدم تغيير النصوص والإصدارات. ونجح فحص الواجهة ببيانات اصطناعية لعرض الأصل والنسخة المستعادة والبحث وإعادة استخدام إصدار قديم. يبدأ فحص بيانات الكاتب الحية بعد دخوله إلى حسابه؛ لا تتضمن هذه النتيجة ادعاء تنفيذ دفعة داخل حساب لم تُستكمل المصادقة عليه.
