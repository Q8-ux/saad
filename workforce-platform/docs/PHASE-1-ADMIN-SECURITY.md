# المرحلة الأولى — لوحة التحكم والأمن

## الهدف
توسعة مشروع Workforce & Safety Platform دون المساس بالواجهة أو نظام نطاق العمل المنجز، وذلك بإضافة طبقة إدارة وصلاحيات وسجل تدقيق قابلة للبناء تدريجياً.

## ما أُضيف في قاعدة البيانات
- أنواع المواقع: محطات توليد، محطات تحويل، مركز تحكم، ومواقع متابعة.
- جدول `Station` لحفظ المواقع والإحداثيات ونطاق الحضور الجغرافي.
- جدول `UserStation` لتحديد المواقع التي يحق لكل مستخدم الوصول إليها.
- جدول `AuditLog` لتسجيل العمليات الحساسة.
- حقول حماية الحساب: محاولات الدخول الفاشلة، القفل المؤقت، آخر دخول، وتاريخ تغيير كلمة المرور.

## الأدوار الحالية
- `SUPER_ADMIN`: إدارة النظام بالكامل.
- `COMPANY_ADMIN`: إدارة الجهة والمستخدمين والمواقع.
- `HR_MANAGER`: إدارة الموظفين والحضور والتقارير.
- `SUPERVISOR`: متابعة المواقع والموظفين المخولين.
- `EMPLOYEE`: استخدام النظام التشغيلي فقط.
- `AUDITOR`: قراءة التقارير وسجل التدقيق دون تعديل.

## قواعد الصلاحيات المطلوبة في الـ API
1. كل استعلام يجب أن يُقيّد بـ `companyId` المستخرج من رمز الدخول، وليس من جسم الطلب.
2. المستخدم غير `SUPER_ADMIN` لا يمكنه إنشاء أو تعديل مستخدم بدور أعلى من دوره.
3. عرض المحطات يكون وفق `UserStation`، باستثناء مسؤولي النظام والجهة.
4. عمليات إنشاء المستخدمين، تعديل الأدوار، تعطيل الحسابات، تعيين المحطات والتصدير تُسجل في `AuditLog`.
5. لا تُرجع حقول `passwordHash` أو معلومات الأمن ضمن أي DTO.

## ضوابط الدخول
- تشفير كلمات المرور باستخدام Argon2id أو bcrypt بمعامل قوي.
- قفل الحساب مؤقتاً بعد 5 محاولات فاشلة.
- مدة صلاحية Access Token قصيرة، مع Refresh Token قابل للإلغاء.
- تخزين Refresh Token بصورة مجزأة وليس كنص صريح.
- تدوير مفاتيح JWT دورياً وعدم وضعها في المستودع.
- فرض HTTPS في الإنتاج.

## ضوابط واجهة الإدارة
- إخفاء أي شاشة أو إجراء لا يملكه الدور الحالي.
- إعادة التحقق من الصلاحية في الخادم؛ الإخفاء في الواجهة ليس حماية كافية.
- تأكيد إضافي قبل تعطيل مستخدم أو حذف تعيين موقع.
- منع عرض سجل التدقيق إلا للمخولين.

## التشفير والحماية
- TLS 1.2 أو أحدث أثناء النقل.
- تشفير النسخ الاحتياطية ووسائط التخزين في بيئة الاستضافة.
- عدم تسجيل كلمات المرور أو رموز JWT أو البيانات الحساسة في السجلات.
- إعداد CORS بقائمة نطاقات مسموحة صريحة.
- تفعيل Helmet وRate Limiting وحد أقصى لحجم الطلبات والمرفقات.
- فحص التبعيات دورياً عبر CI.

## الترحيل
بعد ضبط `DATABASE_URL`:

```bash
cd workforce-platform/apps/api
npx prisma migrate dev --name phase1_admin_security
npx prisma generate
```

في الإنتاج استخدم:

```bash
npx prisma migrate deploy
```

## مبدأ المحافظة على المنجز
تم تنفيذ التوسعة في فرع مستقل باسم `agent/workforce-phase1-admin`. لم يتم تعديل الفرع `main`، ولم يتم استبدال ملفات نظام نطاق العمل أو مشروع اللعبة. الدمج لا يتم إلا بعد المراجعة والاختبار.
