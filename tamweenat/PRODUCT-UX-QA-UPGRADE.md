# تموينات — Product / UX / Conversion / QA Upgrade

## البرومبتات المطبقة
الأقوى للمشروع: 1 مخطط ورحلة المستخدم، 2 التحويل، 4 Design System، 6 الخدمات/القيمة، 9 UX Audit، 10 Code Review، 11 Analytics، 12 QA Gate.

## رحلة المطعم المستهدفة
دخول → كتالوج → بحث/مساعد صوتي → اختيار كمية → سلة → مراجعة السعر → اختيار الدفع → إنشاء الطلب → تتبع → فاتورة → QR → تأكيد الاستلام.

## رحلة الإدارة
دخول منفصل → مؤشرات → مطاعم → طلبات → تجهيز/توصيل → فواتير → إصدار QR → تأكيد الاستلام → Audit.

## تحسينات UX
- المنتجات والأسعار والكمية هي الأولوية في واجهة المطعم، بدون KPIs مبيعات/إيرادات.
- Mobile-first وRTL للعربية، مع EN/UR.
- CTA أساسي واحد في كل مرحلة.
- حالات Loading/Empty/Error/Offline واضحة.
- عدم تكرار أوامر المساعد الصوتي، ولا تنفيذ تغيير السلة/Checkout دون تأكيد.
- إبقاء خط المهند والهوية الكحلي/الأزرق/السلفر.
- صور المنتجات الحقيقية/المعتمدة فقط.

## Conversion
- تقليل الخطوات من المنتج إلى السلة.
- إظهار السعر والوحدة قبل الإضافة وفي السلة.
- إبقاء إجمالي الطلب ظاهرًا أثناء Checkout.
- توضيح حالة الائتمان دون خلطها مع واجهة التسويق.
- إعادة الطلب السابق كإجراء سريع مستقبلًا.

## QR Receipt
- QR لا يحتوي PII أو السعر داخله.
- Token عشوائي مرتبط بالطلب.
- المعاينة والتأكيد يتطلبان جلسة مطعم ومطابقة restaurantId.
- تأكيد مرة واحدة مع receivedAt/receivedBy وسجل Audit.

## Analytics بدون PII
الأحداث: catalog_view, product_view, product_add, cart_open, checkout_start, order_created, order_status_view, invoice_view, receipt_scan, receipt_confirmed, assistant_used, voice_used.
لا ترسل اسم المطعم، الهاتف، البريد، اسم المستخدم، token، أو تفاصيل الفاتورة إلى التحليلات.

## Quality Gate
- لا 404 داخلي.
- اختبار 360/390/768/Desktop.
- RTL/LTR صحيح.
- keyboard/focus واضح.
- QR لا يؤكد بمجرد فتح الرابط.
- لا يمكن لمطعم تأكيد طلب مطعم آخر.
- لا يمكن إعادة تأكيد الاستلام.
- فشل الشبكة لا يكرر إنشاء الطلب.
- المساعد لا يخترع سعرًا أو SKU.
- لا أسرار في GitHub Pages.
