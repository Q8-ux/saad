# مسار دفع سداد

حوّل طلب الدفع إلى ربط فعلي قابل للمراجعة والاختبار، مع الفصل بين إنشاء المسار وتركيبه ونشره ونجاح التحصيل الحي.

## ثبّت المزود والمشروع

1. عيّن البلد والنطاق من دليل المستخدم أو وثائق التاجر. استخدم سداد الكويتية `sadadpay.net` للفيديو المرتبط بهذا المسار؛ لا تستبدلها بسداد السعودية أو قطر.
2. اقرأ تعليمات المشروع والكود الحالي وتتبّع كل مدخل لإنشاء الخدمة، وواجهات الإدارة والنشر. أعد استخدام سياسة الأسعار والجلسات والتخزين الموجودة.
3. اطلب فقط ما لا يمكن استنتاجه عندما يوقف التنفيذ المعتمد. استمر في البرمجة والاختبار دون اختلاق سعر أو تفعيل تحصيل على حساب تاجر غير مؤكد. اجعل السعر والتفعيل قابلين لضبط المدير.
4. اقرأ [عقد سداد](references/sadad-kuwait.md) عند تنفيذ API، و[ربط سابق](references/sabeq.md) عند تعديل سابق. أعد التحقق من الوثائق الرسمية قبل تغييرات مالية؛ دوّن تاريخ التحقق.

## افصل الأسرار عن الملفات العامة

- استخدم متغيرات الخادم أو الخزنة المشفرة القائمة. لا تستخدم `VITE_` أو `NEXT_PUBLIC_` للمفاتيح. لا تضعها في المهارة أو Git أو المواصفات أو السجلات أو أمثلة الاختبار.
- اعتبر مفاتيح الفيديو معلومات اعتماد حساسة. لا ترفق لقطات تعرضها. لا تخمّن حرفاً غير واضح من OCR؛ اقبل القراءة الدقيقة فقط، واختبر المصادقة دون إنشاء فاتورة. أوصِ بتجديد المفاتيح التي ظهرت كاملة، دون تعطيل أعمال البرمجة الممكنة.
- افصل مفاتيح الاختبار والإنتاج. لا تستنتج البيئة من بادئة `ck_` أو `cs_`؛ استخدم النطاق والحساب الفعليين.
- لا تطلب بيانات البطاقة أو OTP ولا تخزنها. افتح صفحة الدفع المستضافة من سداد.
- أرسل الحد الأدنى لإنشاء الفاتورة؛ لا ترسل وقائع القضية أو مستنداتها أو الحوار القانوني أو بيانات عميل لا تحتاجها الفاتورة.

## ابنِ دورة الدفع الصحيحة

1. احفظ سعر الخدمة في الخادم بالفلس الكويتي الصحيح؛ الدينار = 1000 فلس. ارفض الكسور بأكثر من ثلاث خانات. تجاهل السعر والعملة المرسلين من المتصفح واعرض السعر قبل الدفع.
2. أنشئ محاولة محلية قبل الاتصال بسداد: معرف عشوائي، بصمة مدخلات، رمز استحقاق سري، البيئة والمبلغ والعملة ومرجع الطلب. احفظ بصمة الرمز فقط.
3. استخدم نفس المحاولة عند إعادة الاتصال أو النقر المكرر. لا تُنشئ فاتورة أخرى تلقائياً إذا انقطع رد إنشاء الفاتورة؛ أظهر حالة تحتاج إلى التحقق وسوِّها بالمرجع.
4. احصل على رمزي refresh/access من الخادم ثم أنشئ الفاتورة وأعد قراءتها. ركّب رابط الدفع من نطاق سداد المعتمد و`key` المتحقق منه، دون قبول عنوان مزود من العميل.
5. اضبط success/fail لكل فاتورة حيث يدعمه العقد، وأظهر روابط الإعداد المطلوبة للمدير. لا تدّعِ حفظ Webhook في حساب سداد لمجرد إنشاء endpoint محلي.
6. عند العودة أو Webhook، استعلم من الخادم عن الفاتورة. طابق `id/key/ref_Number/currency_Code/amount` مع القيم الثابتة، وتحقق من `status === "Paid"` ومرجع المعاملة وعدم وجود استرداد يناقض الاستحقاق. لا تثق بجسم الإشعار أو باراميتر النجاح وحدهما.
7. احجز الاستحقاق ذرياً قبل أي توليد مدفوع. اربطه ببصمة المدخلات والرمز، وامنع الاستخدام المتزامن، وسجّل استهلاكه مرة واحدة عند اكتمال الخدمة. لا تمنح بيئة الاختبار استحقاقاً في الإنتاج.
   اسمح لصاحب الرمز بتصحيح البيانات قبل الحجز، بعد إعادة التحقق منها، دون فاتورة جديدة. امنع تعديل الطلب الجاري أو المكتمل، وأدرج بصمة المدخلات في شرط الحجز الذري. أعد التحقق من سداد قبل استعادة حجز منتهٍ.
8. حرّر الحجز عند فشل التوليد، دون إسقاط حق العميل أو طلب دفع جديد. احفظ الناتج الآمن مؤقتاً لاستعادته بعد فقد الاستجابة؛ افصل استرجاع الناتج عن إنشاء خدمة ثانية. طبّق مدة الاسترجاع وسياسة حذف واضحة وفق المشروع.
   احفظ معرف الطلب ورمز الاستحقاق فقط في تخزين جلسة المتصفح لاستعادة النافذة بعد إعادة تحميل التبويب؛ لا تحفظ وقائع القضية فيه. لا تعتبر وجود بيانات تمهيدية جديدة إذناً بمسح رمز طلب مكتمل قابل للاسترجاع. ميّز هذا عن إغلاق التبويب أو المتصفح، الذي قد ينهي التخزين.
9. أغلق مداخل API البديلة التي قد تتجاوز اشتراط الدفع. تعذر قراءة سياسة الدفع ليس إذناً بتجاوزها.

## جهّز الإدارة والعميل

- أضف للمدير السعر والبيئة وحالة الاتصال والتفعيل وروابط العودة وWebhook وسجل المحاولات. أعد حالة وجود المفتاح، ولا تُعد قيمته المحفوظة.
- اجعل فحص الاتصال مصادقة فقط. لا تُنشئ فاتورة أو تسحب مبلغاً تحت عنوان «اختبار الاتصال».
- تحقّق من اعتماد حساب التاجر والتسوية للمشروع ومن جاهزية الروابط قبل التحصيل. لا تعتمد اسم شخص أو شركة ظاهراً في فيديو كدليل أنه حساب سابق.
- حافظ على RTL واللغة والخط والهوية القائمة؛ أضف حالات انتظار وإلغاء وفشل ومبلغ واضح ورابط دفع صالحاً. احتفظ ببيانات الطلب عند فتح صفحة سداد.
- لا تجعل تحديث الواجهة دليلاً على تحديث الخلفية أو النطاق الرسمي. تتبّع كل عملية نشر على حدة.

## اختبر قبل التسليم

استخدم بيانات اصطناعية وناقل API معزول. غطِّ: التلاعب بالسعر والمرجع والعملة، إشعار مزور ومكرر، رمز استحقاق مسروق أو خاطئ، نقر متزامن، مهلة إنشاء الفاتورة، انتهاء رمز الوصول، فشل التوليد واستعادة نفس الدفعة والناتج، وفشل مزود الدفع. اختبر واجهات API الحقيقية وسياسة الصلاحيات. لا تكتفِ بفحص وجود أسماء وظائف.

لا تُجرِ دفعاً حقيقياً أو استرداداً أو تجديداً تلقائياً خارج تفويض المستخدم. إذا لم يُختبر التحصيل الحقيقي، اذكر ذلك صراحة. لا تضع علامة اكتمال حي على نجاح اختبارات اصطناعية.
