# إصلاح الموافقة الصريحة على قياس الزيارات — PR #57

## المشكلة والنطاق
المتتبع ينشئ معرفاً دائماً ويرسل page_view قبل أي موافقة، خلافاً لمتطلبات سابق. الإصلاح محدود بواجهة سابق ومصدر الخدمة المطابق، ولا يغير عقود API أو بيانات القضايا أو الدخول أو محرك الصياغة.

## معايير القبول
- FR-001: دون موافقة صريحة محفوظة، لا UUID أو معرف زيارة/جلسة أو طلب قياس أو مؤقت تتبع. القيم القديمة للسماح الضمني لا تُعد موافقة، وتُحذف معرفاتها.
- FR-002: قبول ورفض واضحان بالعربية والإنجليزية والأردية، مع بقاء الخدمات الأساسية متاحة. الاختيار محفوظ في المتصفح والنطاق الحالي فقط.
- FR-003: يمكن سحب الموافقة لاحقاً؛ يتوقف القياس فوراً في الصفحة والتبويبات من النطاق نفسه، وتُلغى الطلبات الجارية وتُحذف معرفات القياس دون مساس بالجلسة القانونية. لا تُرسل أحداث ختامية أو أحداث سابقة على القبول.
- FR-004: يُحترم DNT وGPC والمنع الداخلي والتخزين غير المتاح، وتبدأ الموافقة الجديدة بمعرفات جديدة بعد السحب.
- FR-005: تطابق عقد الموافقة في الصفحة الرئيسية وصفحات السياسة وبناءَي GitHub والخدمة، مع اختبارات تشغيلية للانتقالات والفشل.
- FR-006: بعد السحب اليدوي لشريط الأخبار، يعمل التالي/السابق انطلاقاً من البطاقة المرئية في RTL وLTR، دون تعطيل الحركة التلقائية أو لوحة المفاتيح.
- FR-007: نجاح فحوص المساعد والمذكرات والأخبار والبناءين والنشر المحدود، مع توثيق حدود اختبار المتصفح والنشر الفعلي.

## الحدود
السحب يمنع الإرسال اللاحق، ولا يسترد طلباً وصل بالفعل للخادم أو يمحو سجلاته السابقة. لا تزامن بين نطاق GitHub ونطاق الخدمة بسبب عزل تخزين المتصفح. تحديث PR لا يعني دمجه أو نشره في الإنتاج.
