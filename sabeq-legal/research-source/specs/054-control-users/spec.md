# Feature Specification: حسابات تشغيل مركز تحكم سابق

**Feature**: 054-control-users
**Created**: 2026-10-25
**Status**: Ready for planning
**Input**: إنشاء user1 وuser2 وuser3 وuser5 وit_user بكلمات مرور مختلفة لمركز تحكم سابق.

## User Scenarios & Testing

### User Story 1 - دخول الحسابات الخمسة (Priority: P1)
المستخدم المخوّل يدخل باسمه وكلمة مروره الخاصة.
**Independent Test**: دخول وخروج لكل اسم باعتماد اصطناعي، والتحقق من تهيئة الحسابات الحقيقية بالخدمة المنشورة دون كشف الأسرار.
**Acceptance Scenarios**:
1. حساب مفعّل وكلمة صحيحة → جلسة باسم ذلك الحساب وصفحة المتابعة.
2. كلمة خاطئة أو حساب مجهول أو موقوف → رسالة رفض عامة دون جلسة.
3. الخروج أو الانتهاء أو إلغاء الحساب → توقف الوصول المحمي.

### User Story 2 - صلاحيات تشغيل محددة (Priority: P1)
الحسابات الجديدة تتابع أعمال المركز وتدير المستخدمين بصلاحيات تشغيل محددة.
**Independent Test**: طلب عمليات مسموحة وممنوعة مباشرة إلى الخدمة، دون الاعتماد على إخفاء الواجهة.
**Acceptance Scenarios**:
1. عرض المتابعة والمذكرات والرسائل والتنبيهات والمستخدمين والتشريعات وأوامر المتابعة والتحديثات.
2. طلب إعدادات الربط أو المدفوعات أو المبرمج مباشرة → رفض 403 دون اتصال خارجي أو تعديل.
3. الدخول الإداري السابق يحتفظ بصلاحياته وطريقة دخوله.

### User Story 3 - تسليم وحماية الاعتماد (Priority: P2)
المالك يتسلم خمس كلمات مرور مستقلة بملف خاص.
**Independent Test**: خمسة أسماء وخمس كلمات مختلفة؛ عدم وجود أسرار في المصدر أو الحزم أو استجابات الفحص.
**Acceptance Scenarios**:
1. لا كلمات مرور أو أسرار تهيئة في المستودع أو الواجهة العامة أو استجابة الخدمة.
2. لكل مستخدم جلسة مستقلة؛ المتصفح لا يحفظ كلمة المرور.

### Edge Cases
- يُطبّع الاسم؛ كلمة المرور لا تُختصر ولا تُعدّل.
- الإعداد الناقص يرفض الحسابات الجديدة مع استمرار الدخول الإداري السابق.
- تغيير User-Agent لا يتجاوز قيد المحاولات.
- تغيير اعتماد حساب أو إيقافه يلغي جلساته القديمة دون حساب آخر.
- رابط قسم محظور يعيد حساب التشغيل إلى النظرة العامة.

## Requirements
### Functional Requirements
- **FR-001**: توفير الأسماء الخمسة المطلوبة تماماً؛ لا user4 أو حساب سادس.
- **FR-002**: كلمة عشوائية مستقلة لكل حساب، بطول 24 محرفاً على الأقل، وتسليم خاص.
- **FR-003**: تحقق في الخادم وتمثيل أحادي الاتجاه بملح مستقل وسر إضافي؛ لا اعتماد صريح في المصدر أو السجلات.
- **FR-004**: جلسات مستقلة بحد 8 ساعات وساعة خمول، وخروج فعلي وإلغاء عند تغيير الاعتماد أو الإيقاف.
- **FR-005**: رفض الاعتماد الخاطئ والمجهول والموقوف برسالة عامة واحدة، دون إنشاء جلسة.
- **FR-006**: حد 30 محاولة في الساعة لكل مصدر و8 لكل حساب منه؛ تغيير وكيل المتصفح لا يتجاوز القيد.
- **FR-007**: حصر الصلاحيات حسب US2 في الخادم والواجهة.
- **FR-008**: الحفاظ على الدخول الإداري السابق وتسجيل الزوار وخدمات الموقع والدفع.
- **FR-009**: مدخل عربي RTL واضح على الجوال والكمبيوتر، وتنظيف حقل كلمة المرور بعد النجاح.
- **FR-010**: نشر الخدمة وواجهة التحكم وتوثيق حدود الاختبار الحي.

### Key Entities
- **حساب تشغيل**: اسم فريد وحالة واعتماد محمي وصلاحية تشغيل ثابتة.
- **جلسة إدارة**: مستخدم وانتهاء وخمول ومرجع لنسخة الاعتماد.
- **محاولات الدخول**: مصدر محمي وحساب ونافذة زمنية وعدّاد، بلا كلمة المرور.

## Success Criteria
- **SC-001**: نجاح الحسابات الخمسة في الدخول والخروج، وعدم قبول أي كلمة لحساب آخر.
- **SC-002**: رفض جميع العمليات المحظورة المختبرة حتى بطلب مباشر.
- **SC-003**: لا كلمات مرور أو سر تهيئة في ملف متتبع أو حزمة عامة أو استجابة اختبار.
- **SC-004**: ظهور المدخل على الجوال والكمبيوتر، واستمرار الدخول الإداري السابق.

## Assumptions
- الحسابات كلها تشغيل؛ اسم it_user لا يمنح تلقائياً صلاحيات مالك.
- لا إنشاء لحسابات GitHub أو صناديق البريد.
- لا تسجيل عام للإدارة أو استرجاع بريد في هذا الطلب؛ التغيير والإلغاء بإعدادات الخدمة المحمية.
