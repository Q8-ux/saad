# Implementation Plan: حسابات تشغيل مركز التحكم

## Technical Context
TypeScript وCloudflare Workers/Vinext، وD1 الحالي، وواجهة HTML/JS عربية مستقلة. مصدر التنفيذ /workspace/sites/sabeq-auth-fix؛ مرآة الخادم ../sabeq-legal/research-source، والواجهة ../sabeq-admin-preview. إضافة اعتماد خادم واحد مثبت @noble/hashes@2.4.0 للتحقق PBKDF2-SHA256 بكلفة 600000، بعد HMAC-SHA256 بسر منفصل وملح 16 بايت لكل حساب. لا تخفيض للكلفة بسبب حد WebCrypto.

## Constitution Check
المبادئ I/II: لا تغيير قانوني أو استيراد مصادر. III: الاعتماد في متغيرات سرية فقط، والتسليم خاص، والاختبارات اصطناعية. IV: الحفاظ على الدخول السابق والضيف والدفع والهوية. V: FR/SC وقصص قابلة للاختبار. VI: نطاق سابق فقط. نتيجة التصميم: لا تعارض.

## Design Decisions
1. MANAGEMENT_PASSWORD_USERS إعداد سري بنسخة 1 وقائمة الحسابات؛ MANAGEMENT_PASSWORD_PEPPER سر مستقل. لا اعتماد فعلي في المصدر أو المواصفات.
2. إعادة استخدام management_sessions: تخزين principal داخلي staff:username:credentialTag؛ اشتقاق credentialTag من الاعتماد والسر الإضافي. بعد التحقق يعاد للمكونات معرّف أعمال ثابت staff:username واسم المستخدم ودور operator. الإلغاء أو تغيير الاعتماد يُسقط الجلسة القديمة دون تغيير حالات القراءة المخزنة للحساب.
3. دور operator ثابت للحسابات الجديدة؛ لا قبول حقل role من طلب الدخول. requireManager يعيد الدور، وراوتر الإدارة يتحقق من قائمة GET/POST مسموحة قبل تشغيل أي إجراء. الدخول السابق administrator يحتفظ بصلاحياته.
4. تقييد المحاولات يستخدم بصمة المصدر مع User-Agent ثابت لهذه العملية، فلا يتغير القيد بتغيير الوكيل. POST password-login محدود إلى 4096 بايت. بيانات فشل عامة، وحساب مجهول/موقوف يمر بكلفة تحقق مماثلة.
5. واجهة الدخول تحفظ رمز الجلسة فقط في sessionStorage، وتفرغ كلمة المرور. ترشيح الأقسام حسب صلاحيات الخادم وإرجاع الروابط المحظورة للنظرة العامة.

## Touch Points
- lib/management-password.ts: قراءة الإعداد المحمي، KDF، والتحقق ونسخة الاعتماد.
- lib/management-auth.ts: إصدار جلسات الحسابات الجديدة والتحقق من الدور والإلغاء.
- app/api/management/[...path]/route.ts: عقد الدخول والصلاحيات.
- public/management/admin.js وadmin.css وindex.html: المدخل والأقسام والاستجابة للجوال، مع مرآتها في sabeq-admin-preview.
- package.json وpackage-lock.json: اعتماد الخادم المثبت.
- tests/management.test.mjs: اختبارات الاعتماد والصلاحيات والجلسات والمتصفح الاصطناعي؛ بوابة الإصدار الحالية تشغلها.

## Delivery
اختبار الحدود الفعلية ببيانات اصطناعية، بناء النسختين وفحص عدم تسرب الأسرار، تهيئة الحسابات الحقيقية عبر إعدادات الخدمة السرية، نشر الخدمة وواجهة Pages، محاولة تحقق حي دون كشف بيانات العملاء، وتسليم ملف الاعتماد الخاص. لا تتطلب الخطة ترحيل قاعدة البيانات أو تغيير صلاحيات GitHub.
