# مرسل رسائل التحقق وفحص توثيق النطاق

2026-11-02: طلب المستخدم مراجعة الإيميل والإرسال من noreplay@sabeq.legal بالتهجئة نفسها. إعداد البيئة المقروء حالياً يشير إلى noreply@sabeq.legal؛ إعداد الخزنة له أولوية ويحتاج فحصاً حياً مستقلاً. سجلات الفحص الحالية لم تثبت سبب فشل إرسال جديد؛ لا تُعامل مشكلة توثيق النطاق السابقة كتشخيص حالي مؤكد.

## المتطلبات
- E1: ضبط عنوان الإرسال المطلوب في الإعداد الإداري المعتمد، مع الاحتفاظ بمفتاح المزود الموجود؛ لا إنشاء صندوق بريد أو مفتاح جديد تلقائياً.
- E2: تمكين المشرف من فحص توثيق إرسال نطاق العنوان المحفوظ، دون إرسال رسالة أو تغيير DNS أو صلاحيات المفتاح.
- E3: إظهار الفرق بين غياب المفتاح، رفض المصادقة، مفتاح لا يتيح قراءة النطاقات، غياب النطاق، نقص سجلات التوثيق، وتعذر الاتصال. حفظ الإعداد وحده لا يثبت التوثيق أو وصول الرسالة.
- E4: فحص سجلات SPF وDKIM وإتاحة الإرسال دون اشتراط تفعيل الاستقبال؛ لا كشف مفاتيح أو نطاقات أخرى أو مراسلات المستخدمين.
- E5: أذن المستخدم لاحقاً برسالة اختبار حية من المرسل المحدد إلى بريده الذي حدده في المحادثة. توفير إجراء مشرف محدود برسالة اختبار ثابتة، دون إنشاء حساب زائر أو رمز دخول. لا حفظ عنوانه في المصدر أو المواصفات. التمييز بين قبول المزود ووصول الرسالة لصندوق الوارد. تسجيل الدخول الآمن أو الوصول إلى مزود DNS إن كان مطلوباً يبقى عائقاً صريحاً ولا يُتجاوز.

## القبول
اختبارات protected API لفحص ناجح/ناقص/ممنوع/متعذر وفشل التحويلات؛ إثبات أن جميع طلبات الفحص للمزود GET ولا تحفظ مفاتيح قديمة أو تغير الإعدادات. فحص الواجهة والبناء والنشر، ثم ضبط المرسل والفحص الحي متى توفرت جلسة مشرف آمنة. لا ادعاء وصول بريد حي.
