# المبرمج الاقتصادي داخل إدارة سابق

## User scenarios
- US1 (P1): يختار المدير خدمة سابق الحالية أو بوابة FCC ويحفظ الربط دون كشف المفاتيح بعد الحفظ.
- US2 (P1): يجرب مثالاً اصطناعياً أو يصف مشكلة برمجية ويلصق كوداً، فيحصل على اقتراح واختبار تحقق ومصدر الاستجابة ووقتها.
- US3 (P2): ينسخ المقترح أو يحفظه كتكلّيف في أوامر المتابعة. لا ينفذ الرد أو ينشر تغييراً تلقائياً.

## Functional Requirements
- FR-001: جلسة إدارة معتمدة ومصدر مسموح لكل عملية؛ حد التوليد 20 طلباً في الساعة.
- FR-002: مفتاح FCC في الخزنة المشفرة ويعرض وجوده فقط؛ تغيير الوجهة يتطلب مفتاحاً جديداً. عنوان HTTPS عام دون إعادة توجيه.
- FR-003: اختيار مصدر التوليد صريح بلا تحويل تلقائي لمزود آخر أو ادعاء مجانية خدمة سابق الحالية.
- FR-004: فصل نجاح قراءة نماذج FCC عن نجاح اختبار توليد اصطناعي فعلي.
- FR-005: وصف حتى 2000 حرف وكود حتى 4000 وحد طلب 20KB. رفض أسرار ظاهرة وعدم إرفاق ملفات العملاء أو بريدهم أو مذكراتهم تلقائياً.
- FR-006: عرض الرد كنص آمن مع المدة والتوكنات الفعلية إن توفرت. لا تقدير مالي دون تسعير موثق ولا تسجيل لنص الطلب أو الرد.
- FR-007: حفظ مدخلات النموذج عند الخطأ والإلغاء؛ لا يظهر الرد في قسم آخر. حفظ التكليف باختيار المدير فقط.
- FR-008: قسم إداري في رابط GitHub المستقل، مع هوية اللوحة الحالية وRTL وقراءة الجوال.

## Success criteria
- SC-001: غير المصرح 401 والمصدر المعادي 403، بلا اتصال خارجي.
- SC-002: اختبارات حقيقية لحدود الخزنة والمفتاح والوجهة والإلغاء والرد المقطوع والفشل ومنع التحويل الصامت.
- SC-003: اختبار توليد فعلي ثم نسخ أو حفظ كتكلّيف؛ جاهزية FCC تبقى مرتبطة بعنوان خدمة مستقلة ومفتاحها.
- SC-004: نجاح اختبارات الإدارة والدفع والمذكرات المتعلقة والبناء؛ فصل التحقق المحلي عن الحي.

## Assumptions and boundaries
FCC خدمة Python مستقلة. نركب موصل واجهتها العامة دون تعريض /admin أو جلسات تنفيذها المحلية. خدمة سابق الحالية خيار منفصل بفوترة مزودها وإعداداتها الحالية. لا تغيير في الصياغة القانونية أو المصادر أو الدفع. أول تجربة: اكتشاف خطأ في جمع مبالغ اصطناعية واقتراح إصلاح واختبار.
