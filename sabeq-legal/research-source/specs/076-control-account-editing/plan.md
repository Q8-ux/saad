# خطة إدارة اعتماد اللوحة

1. إعادة استخدام حسابات البيئة الحالية كهوية ثابتة ومصدر للدور والتفعيل والـpepper. حفظ تعديلات الاسم والبصمة فقط في سجل management_vault مشفر؛ لا حاجة لترحيل أو اعتماد جديد.
2. فصل دوال تشفير الخزنة الموجودة في ملف صغير مستقل وإعادة تصديرها من management-auth للحفاظ على المستدعين وتجنب دورة استيراد.
3. دمج التعديلات مع حسابات البيئة على الخادم عند الدخول والتحقق من كل جلسة. معرّف الحساب مبني على الدور والاسم الأصلي؛ تغيير الاسم لا يغير هوية سجلات المكتب. تدوير وسم الجلسة في كل تعديل، بما فيه الاسم وحده.
4. GET/POST control-accounts خلف requireManager وassertManagerAction. دور التعديل administrator فقط؛ الرد قائمة أسماء وأدوار وحالة ورمز نسخة، بلا بصمات أو أملاح. تحديث مشروط بمحتوى الخزنة السابق لمنع السباق. لا إضافة أو ترقية أو إعادة تفعيل حسابات.
5. دمج قائمة «حسابات دخول اللوحة» ونموذج تعديلها داخل SabeqControl/users، قبل حسابات الزوار، مع بقاء واجهات المستخدمين والخدمات القائمة. حقل كلمة مرور جديد فارغ دائماً. إفراغه بعد النجاح أو المغادرة؛ لا تخزينه في المتصفح.
6. اختبارات API اصطناعية في harness الحالي، ومعاينة اصطناعية خارج حزمة الإنتاج. نشر native ثم مرآة GitHub الدقيقة، دون تعديل مشاريع أخرى أو كلمات حقيقية.

## فحص الدستور والمخاطر
لا تغيير قانوني أو مالي. الأسرار والبيانات الخاصة لا تدخل GitHub. Arabic/RTL/Cairo تبقى. تعطيل حساب البيئة يبطل وصوله حتى مع تعديل محفوظ. تعذر قراءة الخزنة أو فسادها يرفض الدخول بدلاً من الرجوع لاعتماد قديم. يظل الدخول الإداري المعتمد عبر الهوية مستقلاً.
