# وصول طلبات المذكرات إلى اللوحة أولاً بأول

إصلاح تأخر تحديث قائمة طلبات المذكرات الحالية في لوحة GitHub والنسخة المستضافة من مركز الإدارة. مصدر الطلبات هو management_memo_requests المشترك؛ لا تنشأ قاعدة ثانية ولا تتغير صلاحيات الدخول أو التوليد أو الدفع.

## دليل العطل ومعايير القبول
- المؤقت الحالي 45 ثانية ويتوقف مع فتح المذكرة أو التركيز على البحث؛ المطلوب فحص السجل الحالي كل 5 ثوانٍ عندما تكون الصفحة ظاهرة.
- تحديث صفوف القائمة وحالات الطلبات دون استبدال نموذج البحث أو نموذج جرد الاسترداد أو محرر المذكرة المفتوحة.
- لا تتداخل طلبات التحديث، ولا تطبق نتيجة قديمة بعد تغيير البحث أو الصفحة أو الجلسة أو التحديث اليدوي.
- العودة إلى الصفحة الظاهرة تفحص الطلبات مباشرة. لا تجرى استدعاءات دورية للصفحة المخفية.
- الأرشيف السابق المحمل يبقى في القائمة؛ الفحص الدوري يستعلم عن المصدر الحالي فقط حتى لا ينتظر اتصال الأرشيف البطيء. التحديث اليدوي يعيد فحص المصدرين.
- فشل التحديث يبقي القائمة ويظهر تعذر التحديث؛ النجاح وحده يغير وقت آخر تحديث.

## حدود الإثبات
الاختبارات اصطناعية؛ التحقق الحي داخل اللوحة يتطلب جلسة إدارية معتمدة. لا تنشأ مذكرات عملاء أو فواتير أو رسائل بريد لإجراء الاختبار.
