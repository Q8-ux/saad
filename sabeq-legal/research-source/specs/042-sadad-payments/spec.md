# Feature Specification: مسار دفع سداد لسابق

**Created**: 2026-10-20 · **Status**: Draft for implementation

## User Scenarios & Testing

### User Story 1 — دفع رسوم المذكرة (Priority: P1)
يدفع الزائر الرسوم المعلنة في صفحة سداد، ثم ينشئ مذكرة واحدة من بياناته المعتمدة بعد التحقق من الدفع. يبقى الطلب المدفوع متاحاً لإعادة المحاولة عند فشل التوليد.

Acceptance: المبلغ المرجعي يحدده الخادم. العودة من صفحة النجاح لا تمنح الخدمة. الإشعارات المزورة أو المكررة، الفاتورة المختلفة، المبلغ المختلف، والطلب المعاد بالتوازي لا تنتج خدمة إضافية. لا تُرسل وقائع القضية إلى سداد.

### User Story 2 — إدارة الربط والتحصيل (Priority: P1)
يضبط المدير مفاتيح سداد وبيئة الربط وسعر المذكرة واشتراط الدفع من لوحة الإدارة المستقلة، ويشاهد المدفوعات وحالة التحقق وروابط الربط.

Acceptance: لا يظهر أي مفتاح محفوظ في الاستجابة أو المتصفح. الإدارة محمية بصلاحياتها القائمة. لا يفعّل التحصيل قبل ضبط سعر موجب واختبار الاتصال وتأكيد حساب التاجر وروابط العودة والإشعار.

### User Story 3 — مسار قابل لإعادة الاستخدام (Priority: P2)
يستدعي المستخدم «مسار دفع سداد» لربط مشاريع أخرى وفق وثائق سداد الكويتية، مع فصل إعداد المسار عن نشر المشروع وعن نجاح التحصيل الحقيقي.

## Requirements

- **FR-001**: استخدام سداد الكويتية الظاهرة في الفيديو، مع فصل الاختبار عن الإنتاج وعدم تخمين واجهاتها.
- **FR-002**: حفظ الأسرار في الخادم فقط؛ لا تنشر مفاتيح الفيديو أو بيانات العميل في Git أو سجل الأخطاء.
- **FR-003**: اعتماد السعر المحفوظ بالفلس الكويتي ومنع التلاعب بالمبلغ والعملة ومرجع الطلب.
- **FR-004**: إنشاء فاتورة واحدة لكل محاولة دفع محددة ومنع تكرار الفاتورة بعد مهلة اتصال غامضة.
- **FR-005**: التحقق من حالة الفاتورة لدى سداد قبل منح الاستحقاق؛ عدم الثقة بالعودة أو جسم الإشعار وحده.
- **FR-006**: ربط الاستحقاق ببصمة المدخلات ورمز عشوائي سري، وحجزه ذرياً لتوليد واحد؛ تحريره عند الفشل وحفظ الناتج الآمن لاستعادته بعد فقد الاتصال.
- **FR-007**: توفير إعدادات ومدفوعات في لوحة الإدارة، دون كشف المفاتيح أو إنشاء عملية مالية أثناء اختبار الاتصال.
- **FR-008**: الحفاظ على الزائر والهوية واللغات وسلامة المصادر القانونية؛ بوابة الدفع تطبق على مداخل التوليد الفعلية.
- **FR-009**: حفظ مهارة مسار دفع سداد واختبارها، ونشر التعديلات المأذون بها مع الفصل بين التنفيذ والاختبار المحلي والحالة الحية.

## Success Criteria

- **SC-001**: لا تمنح حالات الإشعار المزور والمبلغ المختلف والمرجع المختلف خدمة مدفوعة.
- **SC-002**: لا تنتج المحاولات المتزامنة أو المتكررة أكثر من مذكرة ناجحة واحدة لكل دفعة.
- **SC-003**: يستطيع العميل إعادة محاولة طلب مدفوع بعد فشل التوليد دون دفع جديد.
- **SC-004**: يمكن للمدير حفظ الإعدادات وفحص الاتصال ومراجعة المدفوعات بصلاحياته، ولا يستطيع الزائر قراءة هذه البيانات.
- **SC-005**: لا تحتوي الملفات المنشورة على مفاتيح حقيقية أو وقائع قضائية خاصة.

## Edge Cases
توقف سداد، انتهاء رمز الوصول، تكرار الإشعار، تأخر السداد، فشل التوليد، فقد الاستجابة، تغيير المدخلات بعد الدفع، تبديل البيئة أو المفاتيح، وحجب نافذة الدفع.

## Key Entities
إعدادات سداد؛ سياسة تسعير المذكرة القائمة؛ محاولة دفع مرتبطة ببصمة المدخلات؛ فاتورة سداد؛ حجز توليد؛ ناتج توليد خاص قابل للاسترجاع بالاستحقاق.

## Assumptions
الفيديو يثبت موضع إعدادات الربط ولا يثبت صحة المفاتيح أو اعتماد حساب التاجر لسابق. لم يُحدد المستخدم سعر المذكرة؛ يبقى التحصيل غير مفعل حتى يضبطه المدير ويؤكد جاهزية الحساب. لا تسجل رسوماً حقيقية أثناء الفحص. الموقع الرسمي يستضيف واجهة أقدم خارج GitHub؛ أي حد لنشرها يجب أن يُذكر صراحة.
