# مسار المواصفات وضبط التنفيذ — سابق

تم اعتماد GitHub Spec Kit 1.2.1 المثبت وبصماته والتشديد الأمني المراجع. ابدأ من جذر هذا المشروع؛ لا تهيئ مجلداً مشتركاً لمشاريع أخرى. الملف source.json يحفظ المصدر وبصمات التعديلات المعتمدة، وتبقى manifests الأصلية دون استبدال.

دورة الميزة: `$speckit-specify` ثم `$speckit-plan` ثم `$speckit-tasks` ثم `$speckit-analyze` ثم `$speckit-implement` و`$speckit-converge`. التعديل البسيط لا يحتاج الدورة كاملة. هذه أوامر لوكيل البرمجة وليست أوامر terminal.

عند الربط: حدد المصدر المعتمد والحقول والمصادقة والمهلة وإعادة المحاولة وحالات الفشل. يستعمل خادم اللوحة طلبات HMAC مرتبطة بالطريقة والمسار وبصمة الجسم والطابع الزمني ومعرف غير قابل لإعادة الاستخدام. لا ترسل الأسرار إلى المتصفح. لا تفترض أن قاعدة Supabase أو أي واجهة مستقلة تشارك قاعدة سابق تلقائياً.

التحقق: `python -m unittest discover -s tools/spec-kit -p 'test_*.py' -v`. ثم `SPECIFY_FEATURE_DIRECTORY=specs/001-spec-kit-adoption SPECIFY_FEATURE_NO_PERSIST=1 python .specify/scripts/python/check_prerequisites.py --json --require-spec --require-tasks`.

ملفات الأدوات تعليمات تطوير وليست مكونات تمنح الآخرين التحكم. لا تشغل hooks أو أوامر نشر أو دفع آلياً. لا تُدخل بيانات قضايا أو مفاتيح في المواصفات. نجاح هذه الاختبارات لا يثبت التحصيل المالي أو صحة الاستشهادات أو الربط الحي قبل نشر الطرفين وفحصهما.
