# مسار تطوير واختبار لوحة سابق

## User Scenarios & Testing

US1 (P1): يغيّر المطور لوحة الإدارة اعتماداً على مصدرها الحالي وعقد خادم سابق ويشغل اختبارات الرفض والتوقيع والصلاحيات والفشل قبل البناء.

القبول: فشل الاختبار يوقف البناء، ونجاحه يثبت الاختبار المحلي وحده؛ لا تغيير لقاعدة بيانات ثانية أو منح صلاحية تنفيذ أوامر عبر الواجهة.

## Functional Requirements

- FR-001: إعادة استخدام tests/public-service.test.mjs لفحص عقد البيانات والمصادقة والفشل.
- FR-002: ربط الفحص ببناء اللوحة وبفحوص GitHub دون شبكة أو حسابات عملاء حقيقية.
- FR-003: الحفاظ على requireAdminPermission والتوقيع وعدم إعادة استخدام الطلبات وعلى مصدر بيانات سابق الواحد.

## Success Criteria

- SC-001: ينجح الفحص على الحالات الاصطناعية ويفشل البناء عند إخفاق الفحص.
- SC-002: لا أسرار أو بيانات عملاء في التقرير أو الأصول العامة.

## Assumptions

النطاق تعليمات وفحوص التطوير للوحة الحالية فقط؛ لا يعد نجاحها إثباتاً لجلسة إدارة حية أو لتشغيل محرك توليد.
