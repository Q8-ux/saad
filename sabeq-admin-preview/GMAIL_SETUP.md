# إعداد Gmail لمسودات سابق

الربط يستخدم الخادم الحالي ولوحة الإدارة الموجودة، مع المسار المخصص:

```text
https://sabeq-legal-public.centrino.chatgpt.site/api/integrations/gmail/callback
```

هذا هو **Authorized redirect URI** لتطبيق **Web application** في Google Cloud. لا تستخدم صفحة تسجيل دخول Google أو رابط واجهة الإدارة كبديل له.

1. فعّل Gmail API في مشروع Google Cloud.
2. جهّز شاشة OAuth؛ لحساب Gmail شخصي اختر External وأضف حساب المرسل ضمن Test users أثناء التجربة.
3. أضف الصلاحيتين فقط: `gmail.send` و`gmail.readonly`.
4. أنشئ OAuth Client من نوع Web application وسجل رابط العودة أعلاه حرفيًا.
5. داخل لوحة الإدارة، افتح **ربط البريد → Gmail — إرسال مسودات المذكرات**. أدخل Client ID وClient Secret في النموذج المحمي، ثم احفظ.
6. اضغط **ربط حساب Google** واختر حساب المُرسل الذي تعرضه اللوحة. يتأكد الخادم من الحساب الفعلي قبل حفظ التفويض.
7. بعد العودة، أرسل رسالة اختبار للمستلمين المعروضين. قبول Gmail للرسالة لا يثبت وصولها إلى الوارد.

عنوان المُرسل وعناوين المراجعين محفوظة كإعدادات خادم محمية تحت `GMAIL_SENDER_EMAIL` و`MEMO_REVIEW_RECIPIENTS`؛ لا تحفظ عناوين حقيقية أو Client Secret أو Refresh Token في GitHub أو المحادثة.

ترسل المسودة الأصلية المحفوظة كنص عربي كامل مع رقم الطلب ورابط مراجعة محمي. لا يعاد توليدها للإرسال، ولا تُرسل طلبات بلا نص. يُسجّل الإرسال لكل طلب ويُمنع تكراره. المسودات التي انتظرت التفويض يمكن إرسالها من زر **إرسال المسودات المعلقة**؛ الحالات غير المحسومة تحتاج مراجعة قبل أي إعادة إرسال. لا يوجد إرسال رجعي تلقائي للمذكرات القديمة.

تفويض تطبيق Google الخارجي في وضع Testing قد ينتهي بعد سبعة أيام؛ جهّز حالة النشر والتحقق المناسبين لدى Google للتشغيل الدائم. إعداد هذا الموصل لا يغيّر خدمة رموز الدخول أو إعدادات Resend الحالية.
