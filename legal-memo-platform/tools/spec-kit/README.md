# مسار هندسة المواصفات والتنفيذ لسابق

تم تركيب GitHub Spec Kit **v1.2.1** بتكامل Codex في وضع skills، وبسكربتات Python. المصدر المثبت: https://github.com/github/spec-kit/tree/9dca9bf42a031765ee5e5f2371137f2f26967e11 . تفاصيل الإصدار في `source.json`.

## مكانه ونطاقه

ابدأ وكيل البرمجة من `legal-memo-platform/`. إعداد `.specify/` يخص خلفية سابق وواجهة `../sabeq-legal/` فقط. التعليمات في `AGENTS.md` في المستودع الأب تربط المهام بهذا الإعداد. استعمل مسارات المشروع الفعلية في الخطة. لا تهيئ الأداة في جذر المستودع المشترك، ولا تحوّل وثائق أو ملفات مشروع آخر إلى نطاق عمل.

الأوامر والقوالب والسكربتات محفوظة في المستودع وتعمل بعد الاستنساخ دون تثبيت CLI لمجرد تشغيل سكربتات Python. لإدارة الإعداد عبر CLI عند الحاجة:

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@9dca9bf42a031765ee5e5f2371137f2f26967e11
```

لا تُعد تشغيل `specify init --force` على الإعداد الحالي دون مراجعة أثره على الملفات المعدلة. لا يحتاج التركيب إلى مفاتيح API أو قراءة ملفات قضايا.

## دورة الميزة

داخل محادثة Codex من مجلد الخلفية:

1. `$speckit-specify` لوصف النتيجة المطلوبة وحدود التغيير.
2. `$speckit-clarify` عند غموض يؤثر على النتيجة.
3. `$speckit-plan` للخطة المبنية على الكود الحالي.
4. `$speckit-tasks` لمهام مرتبطة بالمتطلبات، ثم `$speckit-analyze` لكشف التناقضات.
5. `$speckit-implement` للتنفيذ، ثم `$speckit-converge` لإظهار ما بقي ناقصاً.

أوامر المهارات تعليمات لوكيل البرمجة وليست أوامر terminal. لا يُستدعى تحويل المهام إلى GitHub Issues تلقائياً. تضبط `SPECIFY_FEATURE_DIRECTORY` الميزة المختارة عند استخدام الأدوات مباشرة؛ ملف `feature.json` محلي ومتجاهَل من Git. مثال التحقق من ميزة التركيب:

```bash
SPECIFY_FEATURE_DIRECTORY=specs/001-spec-kit-adoption SPECIFY_FEATURE_NO_PERSIST=1 python .specify/scripts/python/check_prerequisites.py --json --require-spec --require-tasks --include-tasks
python -m unittest discover -s tools/spec-kit -p 'test_*.py' -v
```

## ما يفيد سابق

| مجال العمل | ما يجب أن يظهر في المواصفة ومعايير القبول |
| --- | --- |
| المساعد القانوني | فهم نوع القضية، أسئلة استكمال النقص، وحدود المعلومات والموافقة المعتمدة |
| توليد المذكرات | الوقائع والطلبات، التعامل مع غياب المصدر، الإلغاء والمهلة، ومراجعة المسودة |
| رفع المستندات | الأنواع والحجم والصلاحيات والفشل وعدم تسرب المحتوى |
| التشريعات والتمييز | مصدر موثق، تطابقه مع الواقعة، وعدم إنشاء حكم عند غيابه |
| العربية والتصدير | الهوية وRTL والقالب وحافظة المستندات وفتح PDF النهائي للتحقق |

هذه معايير عمل للتغييرات التالية، وليست ادعاءً بأن الفحوص الحية لهذه المجالات نفذت أثناء التركيب. أمثلة المواصفات السابقة في `../sabeq-legal/research-source/specs/` تبقى أدلة تاريخية، ولا تُنقل كلها أو تُعلّم مكتملة تلقائياً.

## التحقق والحدود

اختبارات `test_integration.py` تشغّل السكربتات الحقيقية في مجلدات مؤقتة: عزل النطاق داخل المستودع المشترك، إنشاء الميزة، حماية خطة موجودة، رفض خطة مفقودة/قالب فارغ، ومطابقة ملفات الأداة لبصماتها المثبتة أو بصمات التعديلات المحلية المراجعة صراحةً. فحص CI في `.github/workflows/sabeq-spec-kit.yml` يشغّل هذه الاختبارات وفحص المتطلبات.

### مراجعة التركيب — 29 أكتوبر 2026

التركيب موجود مسبقاً بالإصدار المثبت 1.2.1. كشفت إعادة الفحص أن مهاراته العشر تحمل تشديداً أمنياً محلياً لم يكن موثقاً في سجل البصمات: تحديد تفويض المستخدم، منع إنشاء صلاحيات أو وصول خفي، واستبدال طلب تنفيذ hooks التلقائي بطلب مراجعتها والتأكد من التفويض. قورنت الملفات كاملةً بنسخة التثبيت التي اجتازت CI عند الالتزام `b42e1666e7e15c9c2c29523140df14fe6990a7d9`؛ لم تتغير سكربتات التشغيل أو القوالب.

يحفظ `source.json` تحت `local_overrides` بصمة الأصل وبصمة كل تعديل تمت مراجعته. تبقى manifests الأصلية دون تغيير؛ الاختبار يرفض أي تعديل آخر غير مسجل، ويتحقق من أن بصمة الأصل المسجلة تطابق manifest المثبت. قد يعرض CLI المهارات كملفات معدلة؛ هذا متوقع، ولا يبرر استبدالها أو قبول تغييرات جديدة دون مراجعة. هذا توثيق لتعليمات أمان، وليس عزلاً على مستوى نظام التشغيل.

لم تُضف إضافات مجتمع أو خدمة خلفية أو مفاتيح أو اتصالات جديدة، ولم يُرقَّ CLI. نتائج إعادة الفحص المحلية في `validation.json` منفصلة عن التحقق السابق وعن تشغيل GitHub Actions اللاحق. لا يحتاج هذا التغيير إلى نشر واجهة الموقع.

ملفات المسار تُستبعد من صورة Docker عبر `.dockerignore` ولا توجد تعديلات على API أو حزمة الموقع في هذا التركيب. لا تثبت نجاح أدوات التطوير وحدها سلامة التوليد الحي أو صحة المصادر القانونية أو سريان القوانين. التصحيح الصغير لا يحتاج دورة توثيق كاملة. التراجع بإلغاء التزام التركيب المحدود، مع الاحتفاظ بأي مواصفات عمل أضيفت لاحقاً.
