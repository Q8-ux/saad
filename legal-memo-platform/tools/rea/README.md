# مسار الهندسة العكسية وفهم التطبيقات — سابق

ربط فعلي مع [REA](https://github.com/morluto/rea) عبر إصدار `rea-agents@6.5.0` المثبت في الحزمة وملف القفل. الغرض هو فحص كود سابق وتتبع وظائفه وتوثيق الحدود، ضمن بيئة التطوير. لا يُحمّل REA في حزمة المتصفح ولا يُضاف إلى طلبات المستخدم أو محرك الصياغة.

## ما يعمل الآن

1. يجمع `audit.mjs` ملفات الكود المتتبعة في Git فقط، ثم ينسخها إلى مجلد مؤقت خاص.
2. يشغّل REA على ثلاثة أجزاء مستقلة: لقطة مصدر الواجهة، الحزمة المشار إليها في `sabeq-legal/index.html`، وكود الخادم الموجود في `legal-memo-platform`.
3. يستخدم `trace-application-feature` لتتبع ثلاثة مسارات: تحليل المستندات، المساعد، وتوليد المذكرة. عند غياب المطابقة البنيوية، يستخدم `trace-javascript-semantics` لتتبع انتقال نص نقطة الطلب عبر علاقات البيانات المستخرجة من الكود؛ تبقى الحالات الجزئية والملتبسة ظاهرة.
4. ينتج `report.json` و`report.md`: بصمات الملفات ومعرفات الأدلة وأعداد الملفات والتغطية ونتائج التتبع. حذف الأدلة الخام بعد استخراج الملخص يمنع انتقال نصوص الكود إلى التقرير.
5. يشغّل [GitHub Actions](https://github.com/Q8-ux/saad/actions/workflows/sabeq-rea.yml) الفحص عند تعديل الأجزاء المعنية، أو يدوياً. تحفظ ملخصاته سبعة أيام.

التحليل ثابت: العلاقات المستنتجة لا تثبت التشغيل الفعلي أو السبب الجذري لعطل. نجاح المهمة يعني تنفيذ التحليل، ولا يعني أن سابق خالٍ من الأخطاء.

## تشغيل من جذر المستودع

استخدم Node.js `24.19.0` وnpm. على Linux يجب أن يعمل الأمر التالي؛ لا تتجاوز فحص ملكية العمليات الذي يشترطه REA:

```sh
ps -axo pid=,ppid=,pgid=,uid=,stat=,command=
npm ci --omit=optional --ignore-scripts --prefix legal-memo-platform/tools/rea
npm run rea:test --prefix legal-memo-platform
npm run rea:audit --prefix legal-memo-platform
```

التقرير الافتراضي في `legal-memo-platform/tools/rea/reports/`، وهو مستبعد من Git. يمكن تحديد مجلد تقرير خاص باستخدام `SABEQ_REA_REPORT_DIR`. لا يحتاج هذا الفحص إلى مفتاح نموذج، ولا ينفذ طلبات مدفوعة إلى نموذج ذكاء اصطناعي. لا يلزم Hopper أو Ghidra لتحليل JavaScript المستخدم هنا.

## اتصال وكيل البرمجة

يتوفر `.mcp.json` في مجلد الأداة للعميل الذي يدعم إعدادات MCP الخاصة بالمشروع؛ يثبت نفس إصدار REA. يجب فتح `legal-memo-platform/tools/rea/` كمجلد عمل لذلك الإعداد، ثم اتباع آلية تحميل MCP في العميل. وجود الملف في Git لا يسجل خادماً داخل جلسة ChatGPT الحالية، ولا يثبت أن أي عميل آخر حمّله.

للعمل المعتاد استخدم runner؛ فهو يقيد مدخلات الفحص تقنياً. إعداد MCP المباشر يعرض أدوات REA العامة، وتقييد نطاقها تعليمات للوكيل، وليس حاجز صلاحيات يفرضه REA. تجنب تشغيل أدوات التنفيذ أو الفحص على بيانات القضايا.

طلب مناسب للوكيل بعد قراءة التقرير:

> راجع تقرير REA الخاص بسابق. تتبع طلب `/api/legal/analyze-documents` من الواجهة، ثم المساعد وتسليم البيانات إلى `/api/legal/memo`. اربط كل استنتاج بموقعه في الكود ومعرف الدليل. افصل المشاهدة عن الاستنتاج وعن المعلومات غير المتاحة. افحص الخادم المعني فعلياً قبل نسبة عطل إليه. استخدم بيانات اختبار مصطنعة فقط.

## حدود المصدر والتشغيل

- `research-source/` لقطة غير مكتملة: بعض الواردات والمكونات ومسارات API ليست موجودة في هذا المستودع. الغياب عن اللقطة ليس دليلاً على غياب الوظيفة من الخدمة.
- الحزمة الحالية مصغرة، وإعداد بناء GitHub لا يصدر source maps؛ لا تفترض استرجاع أسماء المتغيرات أو السورس الأصلي.
- `api-router.js` ملف قديم غير محمّل في index الحالي. يجب تتبع الحزمة المرتبطة حالياً قبل الحكم على وجهة API.
- مصدر الواجهة يوجّه نسخة GitHub إلى خدمة مختلفة عن الخادم الموجود في `legal-memo-platform`. يلزم التحقق من التشغيل الفعلي والسجلات لإثبات ارتباطهما؛ التحليل لا يساوي بينهما تلقائياً.
- `failed` يبقى فشلاً حتى لو أعاد REA أدلة جزئية. `no-match` لا يثبت غياب الميزة. التغطية `partial` تبقى ظاهرة في التقرير.
- ملفات `.env` وقواعد البيانات والمرفقات والجلسات، والملفات غير المتتبعة والروابط الرمزية، ومشاريع المستودع الأخرى خارج مدخلات runner.
- هذا المسار لا يتحقق من الأحكام أو القوانين، ولا يغيّر مسار التشريعات المرتبط بالملف، ولا يجيز مذكرة دون مراجعة قانونية.

التراجع: إزالة مجلد الأداة وworkflow الخاص به وسطرَي أوامر `rea` من package.json وقسم REA من AGENTS.md. لا يتطلب التراجع استعادة الموقع أو بيانات العملاء، لأن التكامل لا يغير سلوك الإنتاج.

## ما الذي قد نكون أغفلناه؟

مستودع GitHub يجمع نسخة منشورة ولقطة مصدر وخادماً منفصلاً. يجب إثبات أيها يخدم الطلب الفعلي قبل تطبيق إصلاح تشغيلي؛ وإلا قد نصحح كوداً لا تستخدمه الخدمة.
