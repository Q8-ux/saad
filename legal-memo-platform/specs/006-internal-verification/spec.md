# Feature Specification: التحقق الداخلي قبل إصدار سابق

**Feature Branch**: `006-internal-verification`
**Created**: 2026-10-25
**Status**: Approved scope from the owner's implementation request
**Input**: دمج الأداة داخل نظام سابق دون أي إشارة في الموقع إلى اسمها أو وظيفتها، مع تحديد أثرها الفعلي.

## User Scenarios & Testing

### User Story 1 - منع اكتمال تحقق ناقص (Priority: P1)

يحتاج مسؤول الإصدار نتيجة مبنية على تنفيذ فحوص المصادر والمذكرة والصلاحيات، بدلاً من اعتبار وجود الملفات نجاحاً.

**Independent Test**: تشغيل فحوص فعلية ثم حقن فشل وغياب فحص في بيئة اصطناعية.

**Acceptance Scenarios**:
1. Given اجتياز جميع المجموعات المطلوبة، When يطلب إكمال التحقق، Then يسجل النجاح مع عدد الفحوص وبصمة الأدلة.
2. Given فشل أو انتهاء مهلة أو تخطي مجموعة، When يطلب الإصدار، Then يفشل التحقق ولا تسجل نتيجة نجاح سابقة للتشغيل الجديد.

### User Story 2 - تشغيل داخلي بلا أثر مرئي (Priority: P1)

يستمر العميل في استخدام الموقع نفسه دون أسماء أدوات التطوير أو طلبات نموذج إضافية.

**Independent Test**: مقارنة ملفات العرض المتأثرة وفحص حزمة المتصفح بعد البناء.

**Acceptance Scenarios**:
1. Given تحديث داخلي، When يفتح الزائر الموقع، Then تبقى الواجهة واللغات والقوالب كما هي ولا تتضمن اسم الأداة أو وصفها.
2. Given فحص نشر، When يولد التقرير، Then لا يسجل نص قضية أو مصدر خاص أو مفتاح أو مخرجات اختبار خام.

### Edge Cases

غياب الحزمة المثبتة أو اختلاف إصدارها؛ نجاح عملية دون تنفيذ اختبارات؛ فشل عملية فرعية؛ انتهاء المهلة؛ ناتج اختبار يحوي بيانات حساسة؛ تشغيل سابق ناجح يعقبه فشل؛ تعديل مشروع آخر في المستودع المشترك.

## Requirements

### Functional Requirements

- **FR-001**: MUST استخدام إصدار مثبت من الأداة الأصلية لتسجيل شروط الاكتمال، دون ادعاء تشغيل وكلاء Hermes أو اختيار نموذج لم يحدث.
- **FR-002**: MUST تنفيذ مجموعات الفحص المطلوبة فعلياً ورفض النجاح عند فشلها أو غياب اختبارات أو تخطيها أو انتهاء المهلة.
- **FR-003**: MUST ربط فحوص الخادم ببناء الإصدار، وربط فحوص النشر بنشر واجهة سابق.
- **FR-004**: MUST ألا يحتوي تقرير التحقق إلا على معرفات المجموعات والأعداد والمدة ورموز الخروج والبصمات وإصدار المصدر.
- **FR-005**: MUST ألا يتغير عرض الموقع أو مصادر التشريعات أو البيانات أو سياسات اعتماد المذكرات، وألا تنفذ استدعاءات نماذج مدفوعة.
- **FR-006**: MUST قصر الفحوص والتغييرات على سابق، مع الحفاظ على آلية حماية المواقع الأخرى.
- **FR-007**: MUST اختبار رفض الفشل والمهلة والتخطي والأدلة القديمة وغياب الأداة، واختبار الحزمة الأصلية فعلياً.

### Key Entities

- Verification run: هوية فريدة ونسخة المصدر وشروط مطلوبة وحالة نهائية.
- Check receipt: مجموعة فحص ورمز خروج وأعداد ومدة وبصمة، دون النص الخام.

## Success Criteria

- **SC-001**: 100% من حالات الفشل الاصطناعية تمنع إكمال التحقق.
- **SC-002**: لا يعلن نجاح أي مجموعة دون عدد اختبارات موجب، ولا يقبل تشغيل سابق مكان التشغيل الحالي.
- **SC-003**: لا تظهر أسماء الدمج في حزم الزائر، ولا تضاف طلبات نماذج إلى خدمات العملاء.
- **SC-004**: يجتاز بناء الخادم وفحص نشر سابق اختبارات النظام الحقيقي قبل إعلان التنفيذ.

## Assumptions

- المقصود الاستخدام المناسب للأداة في التطوير والتحقق قبل النشر؛ خادم الموقع الحالي لا يشغل Python أو Hermes.
- تشغيل وكلاء مستقلين أو تغيير مزود النموذج أو مفاتيحه خارج هذا الدمج. لا تعتبر تقارير التحقق اعتماداً لسريان التشريعات.
- المصدر الخاص للخادم يبقى في مستودعه المحمي؛ لا ينقل corpus أو ملفات عملاء إلى GitHub العام.
