# Implementation Plan: مسار المواصفات والتنفيذ لسابق

## Technical Context

- Node backend قائم في `legal-memo-platform/`؛ واجهة منشورة ومصدر مرتبط في `../sabeq-legal/`.
- تثبيت GitHub Spec Kit v1.2.1/9dca9bf بتكامل Codex skills وPython؛ لا مكتبة إنتاج جديدة ولا تغييرات API أو قاعدة بيانات.
- اكتشاف جذر `.specify` المحلي أو `SPECIFY_INIT_DIR` يعزل التطبيق داخل المستودع المشترك.

## Constitution Check

استخدم بيانات اختبار اصطناعية فقط، وحافظ على حدود المصادر القانونية والخصوصية والهوية. لا تعلّم فحوص المنتج الحي كمكتملة بسبب تركيب أدوات التطوير.

## Project Structure

- `.specify/`: إعدادات الإصدار، الدستور، القوالب، السكربتات وسير العمل.
- `.agents/skills/speckit-*/`: أوامر Codex الأصلية.
- `specs/001-spec-kit-adoption/`: مواصفة هذا التركيب وخطته ومهامه.
- `tools/spec-kit/`: المصدر والترخيص وتعليمات التشغيل واختبارات التكامل.
- `../AGENTS.md` و`AGENTS.md`: توجيه العمل لسابق فقط.
- `../.github/workflows/sabeq-spec-kit.yml`: CI محدود للتحقق من التركيب.

## Validation

شغّل اختبار التكامل من مجلد الخلفية، وفحص prerequisites مع ميزة التركيب. اختبر السيناريوهات الناجحة والفاشلة في مجلد مؤقت ذي مستودع أب، ثم راجع الفرق والبصمات. راجع CI بعد حفظ التغيير. لا حاجة لإعادة بناء الواجهة لملفات تطوير لا تدخل الحزمة.

## Maintenance — 2026-10-29

قارن التعديلات الأمنية المحلية للمهارات بنسخة التركيب السابقة التي اجتازت CI. احتفظ بملفات المهارات وmanifests الأصلية كما هي؛ وثّق بصمات الأصل والتعديلات المراجعة في `tools/spec-kit/source.json`، واجعل فحص التكامل يقبل هذه البصمات المحددة فقط. أعد فحص العزل وحماية الخطة والمتطلبات، ثم احفظ التغيير المحدود دون نشر المنتج أو ترقية الإصدار.
