# Feature Specification: تركيب مسار المواصفات والتنفيذ لسابق

**Created**: 2026-10-18 | **Status**: Installed; local integration and GitHub CI verified

## User Scenarios & Testing

### User Story 1 — تطوير ميزة دون ضياع المتطلبات (Priority: P1)

يبدأ المطور من خلفية سابق، فيستخدم مهارات Spec Kit المحلية لكتابة مواصفة وخطة ومهام، مع الالتزام بحدود سابق وخصوصية الملفات ومصادر التشريعات الحالية.

**Acceptance Scenarios**:
1. عند استدعاء سكربت من داخل مشروع سابق، تحل مسارات `.specify/` و`specs/` داخل الخلفية حتى لو كان لها مستودع Git أب.
2. عند إعداد خطة ثم إعادة تشغيل خطوة الإعداد، تبقى الخطة الموجودة دون استبدال.
3. عند غياب spec أو plan أو tasks المطلوب، يفشل فحص prerequisites بوضوح.

### User Story 2 — مراجعة الاكتمال بالأدلة (Priority: P1)

يميز المطور بين المهمة المنفذة، سلوك اجتاز الاختبار، ونتيجة نشر حي. يبقى الجزء غير المتحقق معلناً، ولا تُسجل موافقة قانونية آلية.

### Edge Cases

- الاستدعاء من جذر المستودع مع `SPECIFY_INIT_DIR` صريح يجب أن يبقى داخل سابق.
- القالب الفارغ لا ينشئ خطة نجاح وهمية.
- بيانات feature النشطة محلية؛ لا تُثبت مسارات جهاز مطلقة في Git.
- تحديث CLI لا يستبدل دستور سابق أو يضيف مصادر قانونية تلقائياً.

## Requirements

- **FR-001**: تركيب الإصدار 1.2.1 من المصدر المثبت، مع مهارات Codex والقوالب والسكربتات الأصلية وسجل المصدر والترخيص.
- **FR-002**: عزل الإعداد داخل `legal-memo-platform/` وربط تعليمات المستودع به ضمن سابق فقط.
- **FR-003**: تثبيت دستور للخصوصية والدقة وحدود المصادر والهوية ومعايير قبول التغييرات.
- **FR-004**: التحقق بالسكربتات الفعلية من إنشاء الميزة، حماية خطة موجودة، وحالات النقص، مع عدم تعديل مشاريع أخرى.
- **FR-005**: إضافة فحص CI محدود وترحيل تعليمات التشغيل، واستبعاد أدوات التطوير من Docker.

## Success Criteria

- **SC-001**: مهارات Codex العشر مرئية لجرد CLI وتطابق ملفاتها بصمات الإصدار المثبت، أو بصمات تعديلات محلية تمت مراجعتها وتوثيق أصلها وبصمتها صراحةً دون تغيير manifests الأصلية.
- **SC-002**: اختبارات التكامل وفحص prerequisites لميزة التركيب تنجح.
- **SC-003**: فرق Git محدود لإعداد سابق وتعليماته وCI، ولا يتضمن ملفات عميل أو تغييرات API أو حزمة متصفح.

## Scope and risks

التركيب يغيّر أدوات التطوير فقط. لا يثبت معالجة القضايا الحية أو اكتمال مصادر الأحكام أو تغيّر جودة الصياغة فعلياً. قالب المهارة يحتاج وكيل برمجة؛ فحص الملفات ليس تحققاً قانونياً. تغييرات المنتج اللاحقة تحتاج مواصفاتها وأدلة قبولها الخاصة.
