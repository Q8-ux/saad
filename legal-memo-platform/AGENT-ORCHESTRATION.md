# SABEQ Agent Orchestration

طبقة تنسيق للوكلاء الذكية في «مجموعة سابق القانونية»، مستوحاة من نمط Buzz دون إدخال Buzz/Nostr كاملاً إلى الإنتاج.

## الهدف

تحويل تحليل المذكرات من استدعاء AI واحد إلى workflow متعدد المراحل مع فصل المسؤوليات، مصادر قابلة للتتبع، بوابة مراجعة بشرية، وسجل تدقيق.

## الوكلاء

1. `document_agent` — استخراج النص والبيانات الوصفية من المستندات.
2. `facts_agent` — تحديد الأطراف والوقائع والتواريخ والطلبات دون استنتاجات غير مسندة.
3. `law_agent` — البحث في المكتبة القانونية الكويتية وإرجاع النصوص والمصادر فقط.
4. `issues_agent` — ربط المسائل القانونية بالوقائع مع بيان النواقص والتعارضات.
5. `draft_agent` — إعداد مسودة المذكرة اعتماداً حصراً على مخرجات المراحل السابقة.
6. `review_agent` — فحص الاستشهادات والتناقضات والادعاءات غير المسندة قبل التسليم.

## مسار التنفيذ

```
upload/input
  -> document_agent
  -> facts_agent
  -> law_agent
  -> issues_agent
  -> draft_agent
  -> review_agent
  -> human_approval
  -> final/export
```

## قواعد إلزامية

- لا يُعامل أي ناتج AI كرأي قانوني نهائي.
- لا يسمح للـ draft_agent باختراع مصدر أو مادة قانونية.
- كل استشهاد يجب أن يحمل معرف مصدر يمكن الرجوع إليه.
- عند غياب مصدر أو تعارضه، تكون الحالة `needs_review` ولا يتم اعتماد المسودة آلياً.
- الاعتماد النهائي للمذكرة يتطلب `human_approval`.
- لا تُرسل مفاتيح API أو بيانات جلسات المستخدم إلى الواجهة الأمامية.
- الملفات القانونية لا تُنشر في GitHub Pages ولا في سجل التدقيق النصي.

## حالات المهمة

`queued -> running -> needs_review | failed | approved -> completed`

## سجل التدقيق

كل مرحلة تسجل: `workflow_id`, `agent`, `started_at`, `completed_at`, `status`, معرفات المصادر، وhash للمخرجات. لا يسجل النص الكامل للملفات الحساسة.

## التكامل

هذه الطبقة مخصصة للـ backend في `legal-memo-platform`. واجهة `sabeq-legal` تبقى واجهة العرض، وتستدعي API الخادم فقط.

## المرحلة التالية

تنفيذ orchestrator فعلي خلف endpoint مخصص، وربطه بمكتبة القوانين الحالية، ثم إضافة persistence لسجل التدقيق واختبارات تمنع تجاوز بوابة المراجعة البشرية.
