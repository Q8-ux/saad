# عامل الإنتاج لمسار إنشاء المحتوى

عامل منفصل عن استضافة الواجهة. يتضمن محولات فعلية للبحث والصور والصوت والموسيقى والشورتس والبودكاست، مع طابور محدود ومصادقة واستلام ملفات. لا يتضمن خادماً مدفوعاً أو GPU أو مفاتيح مزودين.

## جلب المصادر المثبتة

من `social-request-radar/`:

```bash
python content-worker/install_upstreams.py
```

يجلب المستودعات العشرة إلى `content-worker/upstreams/` عند الـSHA المسجل. لا ينفذ مثبتات المشاريع ولا ينزّل نماذج أو يسجل دخولاً. استخدم `--tool kokoro` مثلاً لجلب مصدر واحد. يفشل عند وجود نسخة مختلفة بدلاً من استبدال عمل سابق. المصادر المتراكبة والتشغيل والنواتج مستثناة من Git.

## تهيئة المحركات

أنشئ بيئة Python منفصلة داخل `upstreams/<tool>/.venv/` لكل محرك يحتاج مكتبات، واتبع متطلبات النسخة المثبتة من المشروع. يختار العامل مفسر تلك البيئة عند وجوده. لا تخلط اعتماديات LDR وdiffusers وPodcastfy في بيئة واحدة دون حل تعارضاتها.

| المحرك | تهيئة المشغل |
|---|---|
| Local Deep Research | شغّل خادم النسخة المثبتة؛ اضبط `RASED_LDR_URL`, `RASED_LDR_USERNAME`, `RASED_LDR_PASSWORD` في بيئة العامل |
| FLUX.2 | ثبّت إصدار diffusers يدعم `Flux2KleinPipeline` وPyTorch الموافق لـCUDA؛ جهز نموذج `black-forest-labs/FLUX.2-klein-4B` محلياً واضبط `RASED_FLUX_MODEL_DIR` لمساره |
| Kokoro | ثبّت المصدر واعتماديات اللغة وespeak-ng عند الحاجة. بعد تجهيز ذاكرة النموذج اضبط `RASED_KOKORO_CACHED=1`، أو اسمح بالتنزيل أثناء المهمة صراحةً عبر `RASED_ALLOW_MODEL_DOWNLOADS=1` |
| ACE-Step | شغّل REST API للنسخة المثبتة واضبط `RASED_ACE_URL` |
| Shorts | ثبّت اعتماديات مصدر `upstreams/shorts` وFFmpeg؛ اضبط `GEMINI_API_KEY` في بيئة العامل. لا يحفظ المفتاح في ملفات الحملة |
| Podcastfy | ثبّت المصدر وهيئ مزودي الكتابة والصوت حسب وثائقه. بعد اختبار إعدادك اضبط `RASED_PODCAST_READY=1` |

فحص الصحة يختبر وجود الاعتماديات والإعدادات المحلية، وليس جودة النموذج أو صلاحية رصيد كل مزود. المهمة نفسها وحدها تثبت إنتاج ملف. محول Kokoro يرفض العربية؛ محول FLUX يستخدم `local_files_only=True` ويحتاج GPU. اللغة الكويتية في سكربت مكتوب لا تثبت جودة النطق.

## التشغيل والربط

هيئ `RASED_CONTENT_KEY` بقيمة سرية عشوائية من ٣٢ حرفاً على الأقل من مدير الأسرار، ثم:

```bash
python content-worker/server.py
```

يستمع افتراضياً على `127.0.0.1:8092`. ضعه خلف HTTPS reverse proxy، واضبط `RADAR_CONTENT_WORKER_ORIGIN` في أسرار مشروع Supabase لأصل HTTPS الخاص به. الأصل لا يختاره المتصفح. بعد ذلك افتح «مصنع المحتوى ← إعدادات التشغيل» وأدخل مفتاح العامل؛ تتحقق البوابة من `/health` وتحفظ القدرة مشفرة. إعداد الأصل وحده لا يكفي لتفعيل محرك ينقصه نموذج أو اعتماديات.

واجهة العامل: `GET /health`, `POST /jobs`, `GET /jobs/{id}`, `GET /jobs/{id}/artifacts/{name}`. جميعها تتطلب Bearer. معرّف المهمة UUID وتغيير محتواها مع إعادة استخدام المعرّف مرفوض. لا يدعم العامل أوامر قادمة من المتصفح، ولا يعرض جذور المستودعات أو الملفات العامة.

حدوده: عملية إنتاج واحدة، ومهمتان معلقة/جارية، و٦ مهام خلال ساعة. مهلة المهمة ١٠ دقائق وملف التنزيل حتى ٢٠ ميجابايت. النتائج والمواد تُحذف بعد ساعة، والتشغيل المعاد لا يستعيد سجل المهام من الذاكرة. حدود الإنفاق لدى المزود منفصلة؛ راقب فواتيره. عند مهلة محرك يتصل بخدمة بعيدة تحقق من حالة المهمة هناك قبل إرسال أخرى.

حزم OpenCreator وShort Video Factory وSocial Media Agent تُفتح وتُراجع في تطبيقاتها. لم نعرضها كموصلات HTTP جاهزة دون عقد موثق، ولم يُضف نشر تلقائي أو جلسات حسابات اجتماعية.
