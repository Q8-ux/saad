# AI Chess Kuwait — UX / Product / QA Upgrade Plan

## الهدف
تحسين المشروع وفق أعلى البرومبتات تأثيرًا عليه: هندسة رحلة المستخدم، UX، Design System، مراجعة الكود، الأداء وإمكانية الوصول، ثم القياس.

## رحلة المستخدم المستهدفة
1. فتح اللعبة.
2. اختيار: لعب سريع ضد AI أو تسجيل الدخول للعب الجماعي.
3. اختيار المستوى عند AI فقط.
4. بدء المباراة فورًا.
5. أثناء اللعب: حالة الدور واضحة، التلميحات للمبتدئ، الصوت والمشاركة دون تشتيت.
6. بعد المباراة: النتيجة، ELO عند اللعب الجماعي، إعادة مباراة أو مشاركة.
7. عند الانقطاع: استكمال المباراة السابقة بأمان.

## التغييرات ذات الأولوية
- جعل الرقعة واللعب هما العنصر البصري الأول، وتأخير عناصر الحساب والإعدادات الثانوية.
- تبسيط Mobile UX وتقليل الحمل البصري أعلى الرقعة.
- الحفاظ على العربية RTL والإنجليزية والأوردو.
- إبقاء خط المهند والهوية الكحلي/التركواز/الأزرق/الذهبي.
- Touch targets لا تقل عن 44px للعناصر التفاعلية الأساسية.
- حالات focus واضحة ودعم prefers-reduced-motion.
- تحسين aria-labels والحالة الحية للعبة.
- عدم كسر matchmaking والغرف الخاصة وELO وإعادة الاتصال.
- عدم كشف مفاتيح Supabase أو خدمات التحليل في الواجهة.

## قياس النجاح
أحداث مقترحة:
- chess_game_start
- chess_mode_selected
- chess_login_success
- chess_matchmaking_start
- chess_room_created
- chess_hint_used
- chess_game_resumed
- chess_game_completed
- chess_share

لا ترسل البريد أو اسم المستخدم أو رمز الغرفة إلى Analytics.

## Quality Gate
- اختبارات Python الحالية تمر.
- لا أخطاء Console أساسية.
- اختبار 360px / 390px / tablet / desktop.
- التنقل بلوحة المفاتيح يعمل.
- عدم فقد سجل النقلات عند الاستكمال.
- بدء مباراة جديدة يلغي الطلبات القديمة.
- مشاركة الدعوة تعمل مع fallback.
- فشل الشبكة يعرض رسالة مفهومة ولا يفسد حالة المباراة.
